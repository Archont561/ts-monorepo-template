# AGENTS.md — @myorg/badges

## Rules

- Badges are **static Markdown in README files** — not generated by `mdocs`. Edit the README, never a template.
- Update badge URLs when you add, rename or remove a workflow, or when the published package name changes.
- `@myorg` in the npm version badge is replaced by the scaffolder's scope rewrite; the owner/repo in CI and Codecov URLs is replaced by identity resolution. Do not hardcode a real owner or scope here.
- Keep the root README to at most five badges — badge sprawl reads as insecurity, not rigor.
- Coverage badges must stay truthful: a badge pointing at Codecov means the CI upload step exists.

## Where badges live

| File | Badges |
| :--- | :--- |
| `README.md` (root) | CI, Coverage, Coverage HTML, License, Bun |
| `packages/external/README.md` | CI, Coverage, License, Bun, npm version |
| `packages/internal/README.md` | CI, Coverage, License, Bun |
| `packages/native/npm/native/README.md` | CI, Coverage, License, Bun, Rust |
| `apps/example/README.md` | CI, Coverage, License, Bun |

## Before marking a task done

- [ ] Every README referenced above still has a badge row that matches the current workflows
- [ ] No badge URL contains a hardcoded owner or scope
- [ ] `bun run coverage:check` passes, so the coverage badge is not advertising a failing gate

## UnoCSS

> Opt-in atomic CSS — disabled by default, enabled via scaffold prompt. Data-driven via `package.json` `scaffold` metadata + `setup.ts`. No TEMPLATE-ONLY for unocss in example — via file deletion.

- `configs/unocss` (`@myorg/unocss`) provides `unocss`, `uno.config.ts` with `presetWind3`, transformers
- Template has `apps/example/public/index.html` (plain) + `index-unocss.html` (UnoCSS utilities, CDN runtime)
- When `false` (default), deletes `index-unocss.html`, `uno.config.ts`, `uno.css`, `index-plain.html` via `extraRemovals` + `filePatternsToRemove` (`**/index-unocss.html`, `**/uno.css`, `uno.config.*`) + `fileRegexesToRemove` (`unocss`, `index-unocss`) + `appDepsToRemove` (`@myorg/unocss`) — no TEMPLATE-ONLY
- When `true`, keeps + runs `setup: configs/unocss/src/setup.ts`:
  1. Ensures `uno.config.ts` exists (extends baseConfig)
  2. Moves `index-unocss.html` → `index.html` (replaces plain with UnoCSS version per spec: opt-out delete, opt-in replace)
  3. Adds `@myorg/unocss` to example app
  4. Ensures `/uno.css` route in example server
- Example bundle handling (no TEMPLATE-ONLY):
  - `apps/example/src/index.ts` has `/uno.css` route always, returns generated CSS or fallback note via file existence check
  - `src/pages/index.ts` tries unocss html first, then plain — runtime check
  - `src/pages/api/index.ts` lists `/uno.css` when `uno.config.ts` exists — runtime check
  - `public/uno.css` served via `/uno.css`, generated by the app's own build (`apps/example` → `build:css` → `munocss build`), never by a root/global script

| Option | Result |
| :--- | :--- |
| `false` | No unocss files, plain index.html (via file deletion) |
| `true` | index-unocss.html → index.html, uno.css route, deps (via setup.ts) |
